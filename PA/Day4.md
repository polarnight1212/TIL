## 2. Jupyter Notebook
실습 이력을 기록하고 시각적으로 확인하기에 최적화된 도구입니다.

- **작동 원리**:
  - 사용자 화면은 브라우저 interface일 뿐, 실제 코드는 **Jupyter Server**를 거쳐 **Kernel** 메모리 상에서 실행됨.
  - 정의된 변수와 `import` 상태는 모두 커널 메모리에 유지됨.
  - `!python -m ipykernel install` 단계를 누락할 경우 `ImportError`가 발생할 수 있음.
- **파일 구조**: `.ipynb` 파일은 코드 셀의 소스코드와 실행 출력을 모두 담은 JSON 형태의 텍스트 파일로, Git 버전 관리가 가능함.

### ⚠️ 셀(Cell) 실행 규칙 (독립적이지 않음)
- 모든 셀은 하나의 동일한 커널 메모리를 공유함.
- 위아래 셀을 오가며 임의 순서로 실행할 경우, 눈에 보이는 코드 순서와 실제 실행 상태(이력)가 어긋남.
- **제출 전 필수 체크**: `Kernel` -> `Restart Kernel and Run All Cells` 메뉴를 실행해 처음부터 끝까지 한번에 정상 작동하는지 확인.

### 자주 사용하는 단축키 5선
| 단축키 | 기능 |
| :--- | :--- |
| **`Shift` + `Enter`** | 셀 실행 후 다음 셀로 이동 |
| **`Ctrl` + `Enter`** | 셀 실행 후 해당 셀에 머무름 |
| **`Esc` $\rightarrow$ `A` / `B`** | 현재 셀 위(`A`) / 아래(`B`)에 새 셀 삽입 |
| **`Esc` $\rightarrow$ `M` / `Y`** | 마크다운 셀(`M`) / 코드 셀(`Y`)로 전환 |
| **`Esc` $\rightarrow$ `D`, `D`** | 선택한 셀 삭제 |

> 💡 **Tip**: 반복적으로 두 번 이상 재사용되는 코드는 `.ipynb` 대신 `.py` 모듈로 분리하여 관리하는 것이 원칙입니다.

## 3. 핵심 자료구조 (List, Tuple, Dict, Set)

| 자료구조 | 특징 | 탐색 시간 복잡도 | 주요 용도 |
| :--- | :--- | :--- | :--- |
| **List** | 순서가 있는 가변(Mutable) 목록 | $O(N)$ (전수 조사) | 데이터 추가/삭제가 잦은 경우 |
| **Tuple** | 순서가 있는 불변(Immutable) 묶음 | $O(N)$ | 변경되면 안 되는 값 보존 |
| **Dict** | Key-Value 형태의 표 구조 | $O(1)$ (해시) | 이름/키를 통한 빠른 조회 |
| **Set** | 중복을 허용하지 않는 집합 | $O(1)$ (해시) | 중복 제거, 빠른 소속 검사 |

### 🚀 Dict / Set의 탐색 성능이 빠른 이유
`dict`와 `set`은 내부적으로 **해시 테이블(Hash Table)** 구조를 사용합니다.
포함 검사(`x in a`) 시, 키 값을 해시 함수에 넣어 주소를 바로 계산하므로 데이터가 100만 개 이상 쌓여도 **$O(1)$**의 속도로 즉시 탐색합니다.

## 4. 코드 구조화: 함수 $\rightarrow$ 모듈 $\rightarrow$ 패키지
코드가 복잡해질수록 관리 효율을 위해 상위 단위를 활용해 묶어줍니다.

- **함수 (Function)**: `def`로 정의하며, 단 하나의 책임(일)만 담당.
- **모듈 (Module)**: `.py` 파일 하나. 관련 함수/클래스들의 집합.
- **패키지 (Package)**: 모듈들을 담고 있는 디렉터리(폴더) 구조.

```text
robot_utils/                 ← 패키지 (Package)
├── __init__.py
├── kinematics.py            ← 모듈: 좌표 및 속도 계산
└── safety.py                ← 모듈: 정지거리 및 한계 검사
