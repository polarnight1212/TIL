# OpenCV 기초

## 이미지 = Numpy

해석: 컬러 이미지는 (높이 H, 너비 W, 채널 3) 의 uint8 배열입니다. 주의 두 가지 — ① 인덱싱은 img[y, x] (행=세로 먼저), 원점은 왼쪽 위, y는 아래로 증가합니다. ② OpenCV의 채널 순서는 RGB가 아니라 BGR입니다(역사적 이유). Matplotlib으로 보여줄 땐 img[:, :, ::-1] 로 뒤집어야 색이 맞습니다.


```python
roi = img[100:300, 200:400]          # 슬라이싱 = 관심 영역(ROI) 잘라내기
img[img < 30] = 0                    # 불리언 마스킹 = 어두운 픽셀 끄기
gray = img.mean(axis=2)              # 축 연산 = 간이 그레이스케일
```

- `uint8` 은 0~255에서 **넘치면 감긴다**(wrap)는 함정이 있습니다: `np.uint8(250) + np.uint8(10) = 4`. 밝기 연산은 `cv2.add`(포화 연산) 또는 float 변환 후 처리합니다.
- 동영상은 이미지의 시퀀스일 뿐입니다: `cap = cv2.VideoCapture(0)` → 루프에서 `ret, frame = cap.read()`.



## 2, HSV

**현상** — 낮에 잘 잡히던 빨간 공 검출기가 저녁에 형광등을 켜면 절반만 잡히고, 창가로 가면 아예 놓칩니다. 코드는 한 줄도 바뀌지 않았는데 결과가 달라집니다.

**직관** — 조명이 바뀌면 **빛의 양**이 바뀜는 것이지 **색 자체**가 바뀜는 것은 아닙니다. 그런데 BGR은 밝기 정보가 세 채널에 골고루 섞여 있어서, 조명이 흔들리면 세 숫자가 함께 움직입니다. 그렇다면 "무슨 색인가"와 "얼마나 밝은가"를 **분리해 놓은 좌표계**를 쓰면 조명에 강한 기준을 만들 수 있습니다.

**HSV**는 색을 사람의 직관대로 분해합니다.

 - H(Hue) = 색상 -빨강, 초록, 파랑 = 0 ~ 179도 = 조명변화에 강함
 - S(Saturation) = 채도  = 0~255 = 조명변화 중간
 - V(value) = 명도 = 0 ~ 255 = 약함

 
## 3 . 필터링


카메라 픽셀에는 센서 노이즈가 섞여 있고, 그대로 `inRange` 를 하면 마스크에 소금 뿌린 듯한 점이 남습니다. 6강(모듈 ①)에서 ADC 신호를 EMA로 다듬었듯, 이미지도 **블러(저역통과)** 로 다듬고 시작합니다.

| 필터 | 원리 | 특징 |
| --- | --- | --- |
| 평균 블러 `blur` | 주변 픽셀 평균 | 빠르지만 경계도 뭉갬 |
| **가우시안** `GaussianBlur` | 거리 가중 평균 | 자연스러운 표준 선택 |
| **미디언** `medianBlur` | 주변의 중앙값 | 소금·후추 노이즈에 특효 |
| 양방향 `bilateralFilter` | 색이 비슷한 이웃만 평균 | 경계 보존, 느림 |

```python
smooth = cv2.GaussianBlur(img, (5, 5), 0)     # 커널 크기는 홀수
```

이 연산의 정체는 **컨볼루션** — 작은 커널 행렬을 이미지 위로 밀며 내적하는 것입니다(Lv.1 6강의 브로드캐스팅 감각). 커널을 바꾸면 블러가 아니라 **에지 검출**(Sobel)도 됩니다 — 그리고 이 "커널을 학습으로 찾자"가 모듈 ④에서 만날 CNN의 출발점입니다.
