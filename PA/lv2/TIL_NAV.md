# NAV

## 스택 구조
- BT Navigator: 계획, 제어, 복구 작업 조율
- Planner: 경로 / Controller: 속도 명령
- Costmap: 충돌 위험과 통과 비용

## 경로와 궤적
- 경로는 공간에서 어디를 지나갈지를 나타낸다
- 궤적은 시간에 따른 상태/속도까지 포함
- planner가 경로를 만들고, controller가 로봇 운동 제약과 장애물을 고려해 추종

## TF 구조
- map → odom: 저장 지도 주행에서는 AMCL이 전역 위치 보정
- odom → base_footprint: Gazebo 또는 오도메트리가 연속 이동 발행
- base_footprint → 센서: URDF에 정의된 고정 변환

## AMCL (Adaptive Monte Carlo Localization)
- 적응형 몬테카를로 위치 추정
- 알려진 2D 지도에서 로봇의 위치와 방향(x, y, θ)을 추정
- 여러 위치 가설을 입자로 표현하며 불확실성에 따라 입자 수를 조절한다

### 입자 필터 과정
- 예측: 오도메트리 이동량과 잡음을 반영해 입자를 움직인다
- 갱신: 각 입자의 위치에서 예상되는 지도와 실제 LiDAR 관측을 비교
- 재표본화: 관측과 잘 맞는 가설이 다음 입자 집합에 더 많이 남는다

### 레이저 모델
- `laser_model_type`: 레이저 끝점과 지도 장애물 간 거리로 관측 적합성을 평가
- `sigma_hit`: 0.2 m / 끝점 거리 오차 모델 폭 / 너무 좁으면 작은 불일치에도 민감해진다
- `z_hit` / `z_rand`: 0.5 / 0.5 / 정상 관측 / 무작위 관측 혼합 가중치

### Odometry vs MCL/AMCL vs SLAM
기술적으로 정확히 무엇이 다른가?

| 구분 | Odometry | MCL / AMCL | SLAM |
|---|---|---|---|
| 주된 목적 | 이동량 추정 | 지도 안에서 위치 추정 | 지도 작성과 위치 추정 |
| 기존 지도 필요 | 불필요 | 필요 | 일반적으로 불필요 |
| LiDAR 사용 | 선택적 | 일반적으로 사용 | 일반적으로 사용 |
| 휠 엔코더 활용 | 핵심 입력 중 하나 | 이동 예측에 활용 | 초기 이동 추정 등에 활용 |
| 오차 보정 | 별도 보정 없으면 누적 | 지도·센서 관측으로 보정 | 지도와 관측 간 제약으로 보정 |
| 결과 | 이동 추정값 | 현재 위치의 확률적 추정 | 지도와 로봇의 위치 추정 |

- MCL도 Odometry를 사용한다. 둘은 서로 대체하는 관계가 아니다.
- MCL은 Odometry를 통해 로봇이 어디로 이동했을지 예측하고, LiDAR 관측값과 지도 사이의 일치도를 확인해서 그 예측을 보정할 수 있다.

## 전역 경로 계획

### 지도와 Costmap
- 점유 지도: 공간의 점유 상태
- Costmap: 주행 위험을 비용으로 표현
- 같은 거리라도 벽 근처 경로의 비용이 더 높을 수 있다

### Dijkstra(다익스트라)
- 출발점부터 누적 비용 g가 가장 작은 후보를 순서대로 확장
- 최소 비용 경로
- 목표 방향의 휴리스틱 없이 탐색하므로 넓은 영역을 살필 수 있다

### A*(에이스타)
- 누적 비용 g와 목표까지의 예상 비용 h를 합한 f = g + h로 후보 선택
- h가 목표 방향 탐색을 도와 불필요한 확장을 줄일 수 있다

### Dijkstra vs A* 비교
- 우선순위: Dijkstra는 누적 비용, A*는 목표 추정 비용까지 사용
- 비교 조건: 같은 지도, 같은 비용. 알고리즘 이름만으로 경로 길이·안전성을 단정하지 않는다
- 선택 실험: 시간, 성공률, 경로 / 좁은 미로와 넓은 공간에서 각각 반복 비교

## 지역 제어

### controller의 역할
- 현재 위치, 속도, 경로, 주변 costmap을 받아 다음 속도 명령을 계산한다
- waffle은 선속도 vx와 각속도 wz를 사용한다
- 새 장애물을 피하려면 관측 갱신과 필요시 전역 재계획도 함께 작동한다

### DWB 원리
- 속도 후보를 샘플링하고 짧은 궤적을 예측한다
- critic이 장애물 / 경로 거리 / 목표 방향 등을 평가한다
- 유효한 후보 중 가중 비용이 작은 궤적의 속도 명령을 선택
- 로봇이 S자로 움직임 - 계속 바운더리를 판단해야 해서
- 프로세스를 제일 작게 먹음 - 부하가 적음
- 장애물이 로봇이 오기 전에 사라진다는 가정하에 만듦 - 사람이 피해라

### MPPI
- 장애물, 경로, 목표를 비용으로 표현
- 벡터화된 계산
- 샘플 수, 예측 길이, critic 수가 계산 시간을 바꾼다
- 제어 주기를 지킬 수 있는지로 선택
- 리소스 많이 잡아먹음
